## 1. Context & Task Scope

### Objectives
1. Implement type-safe, production-ready Pydantic v2 data models in `src/schemas.py` matching the authoritative specifications in [`.agents/docs/SPECIFICATIONS.md`](file:///c:/Users/Saksham/Git/poc/AIAgents/code-orchestration/.agents/docs/SPECIFICATIONS.md).
2. Substrate Models (mapping 1:1 to `hse-easy-mock` MCP output contracts while maintaining strict substrate isolation):
   - `RegulatoryUpdateSummary`: Tier 1 lightweight summary model for HSE regulatory updates.
   - `RegulatoryDocument`: Tier 2 comprehensive document model with full markdown content, legal obligations, and penalty summaries (inheriting from `RegulatoryUpdateSummary`).
   - `CitationVerificationResult`: Legal citation verification result returned by legal QA tools.
   - `TDIServiceOffering`: Commercial service offering and pre-approved CTA templates.
3. Pipeline Internal Models (powering procedural orchestration and Strands agent worker contracts):
   - `PipelineScope`: Structured extraction boundaries from raw user prompts with unconstrained draft ceiling (`max_drafts=None`) by default.
   - `ArticleDraft`: Core article components generated by Writer Agent (`headline`, `executive_summary`, `article_body`, `tdi_cta`).
   - `QAReport`: Compliance audit emitted by QA-Legal Agent with tri-state status (`PASS`, `WARNING`, `ERROR`).
   - `DraftMetadata`: Complete record required to render `.agents/templates/draft.md` including telemetry and revision count.
   - `RevisionPayload`: Strongly-typed revision input passed directly to the Writer Agent on revision loops (Rule 2 & Rule 3).
4. System Enumerations & Exit Codes:
   - `PipelineExitCode`: Standardized integer exit codes (`SUCCESS=0`, `NO_UPDATES=1`, `MCP_ERROR=2`, `PARSER_ERROR=3`, `PERSISTENCE_ERROR=4`).
5. Ensure strict model configuration across all models (`model_config = ConfigDict(extra="ignore", populate_by_name=True)`), zero unstructured dictionary leaks, and comprehensive test coverage in `tests/test_unit/test_schemas.py`.

## 3. Strict TDD Strategy (Rule 7)

Execution is strictly divided into 3 small, incremental TDD batches. Under no circumstances will all tests be written upfront. For each batch, the implementation agent will write targeted tests, observe failure under `pytest`, write minimal implementation in `src/schemas.py`, and refactor.

### Batch 1: Substrate Data Models
* **Red:**
  - Create `tests/test_unit/test_schemas.py`.
  - Author tests for substrate models:
    - `test_regulatory_update_summary_validation()`: Instantiation with valid fields, literal constraints on `source`, `doc_type`, `impact_level`, default `topic_tags`, and validation errors on missing required fields or invalid literals.
    - `test_regulatory_document_inheritance_and_fields()`: Verifies inheritance from `RegulatoryUpdateSummary`, additional fields (`status`, `target_sectors`, `key_obligations`, `penalties_summary`, `related_citations`, `content_markdown`), and default factories.
    - `test_citation_verification_result_validation()`: Validates status literals (`in_force`, `amended`, `repealed`, `unrecognized`), boolean `is_valid`, and optional fields.
    - `test_tdi_service_offering_validation()`: Validates required CTA fields, value proposition, and `applicable_sectors` default.
    - `test_substrate_models_extra_ignore()`: Asserts that arbitrary unexpected upstream JSON fields are ignored without raising validation errors (`extra="ignore"`).
  - **Expected Failure Mode:** `ImportError` or `AttributeError` because models are not yet defined in `src/schemas.py`.
* **Green:**
  - Implement `RegulatoryUpdateSummary`, `RegulatoryDocument`, `CitationVerificationResult`, and `TDIServiceOffering` in `src/schemas.py`.
  - Run `uv run pytest tests/test_unit/test_schemas.py`.
  - Verify all Batch 1 tests pass.
* **Refactor:**

## 6. Questions & Decisions for Human Approval

1. **Substrate Model Independence:** Defining substrate models directly in `src/schemas.py` (rather than importing from `mcp-server.models`) maintains strict architectural decoupling so `code-orchestration` only depends on the public MCP interface and specifications, not internal server code.
2. **Exit Code Enum:** Included `PipelineExitCode(IntEnum)` in `src/schemas.py` to provide a single typed source of truth for the CLI exit codes documented in `SPECIFICATIONS.md` Section 6.
3. **Extra Field Tolerance:** Configured `extra="ignore"` on all models so unexpected future fields emitted by the MCP server do not cause pipeline crashes.
