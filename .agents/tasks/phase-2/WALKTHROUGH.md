## 2. Component Details & Architectural Rationale

### A. Substrate Models (MCP Interface Layer)
- **`RegulatoryUpdateSummary`**: Lightweight Tier 1 notice model representing EUR-Lex, Gazzetta Ufficiale, and INAIL updates. Fields include `doc_id`, `source`, `doc_type`, `official_reference`, `title`, `publication_date`, `impact_level`, `topic_tags`, `summary`, and `canonical_url`.
- **`RegulatoryDocument`**: Tier 2 comprehensive model inheriting from `RegulatoryUpdateSummary`, adding statutory metadata (`status`, `target_sectors`, `key_obligations`, `penalties_summary`, `related_citations`, `content_markdown`).
- **`CitationVerificationResult`**: Validation result returned by legal citation verification tools, enforcing valid status literals (`in_force`, `amended`, `repealed`, `unrecognized`).
- **`TDIServiceOffering`**: Commercial consulting and pre-approved CTA offering schemas for TDI lead generation.
- **Architectural Isolation:** All substrate models are natively declared in `src/schemas.py` with `model_config = ConfigDict(extra="ignore", populate_by_name=True)`. This ensures that unexpected server-side fields are tolerated without breaking pipeline operations, and eliminates direct internal code coupling to `mcp-server`.
- **Live MCP Substrate Compatibility:** Validated against the live `hse-easy-mock` server outputs:
  - `server.list_regulatory_updates()`
  - `server.search_regulatory_docs()`
  - `server.get_document_by_id()` across all corpus documents
  - `server.verify_legal_citation()` on valid and invalid citations
  - `server.get_tdi_service_offerings()` across multiple topics
  - `server.mcp.call_tool()` FastMCP JSON roundtrips

### B. Internal Pipeline Contracts
- **`PipelineScope`**: Structured parameter boundary model parsed from natural language prompts. Crucially, `max_drafts` defaults to `None`, preserving **Rule 4** (unconstrained candidate processing by default).
- **`ArticleDraft`**: 4-part article structure (`headline`, `executive_summary`, `article_body`, `tdi_cta`) generated by the Writer Agent.
- **`QAReport`**: Legal and compliance evaluation report featuring tri-state status (`PASS`, `WARNING`, `ERROR`), `verified_citations`, `issues`, and `review_notes`.
- **`DraftMetadata`**: Full composition model providing every field needed by `.agents/templates/draft.md`, including run telemetry (`latency_seconds`, `estimated_cost`, `total_tokens`), revision count, and unresolved error tracking.
- **`RevisionPayload`**: Strongly-typed payload passed to the Writer Agent on revision loops (Rule 2 & Rule 3), cleanly encapsulating the previous `ArticleDraft` and the `QAReport` without loose dictionaries.

### C. Standardized Error Handling
- **`PipelineExitCode(IntEnum)`**: Type-safe enumeration of pipeline exit codes defined in `SPECIFICATIONS.md` Section 6 (`SUCCESS=0`, `NO_UPDATES=1`, `MCP_ERROR=2`, `PARSER_ERROR=3`, `PERSISTENCE_ERROR=4`).
